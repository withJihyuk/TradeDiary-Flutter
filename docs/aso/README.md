# 한국 스토어 ASO 등록·미리보기 제작안

작성일: 2026-10-18. 미리보기 제작일: 2026-10-19. 대상은 한국어 App Store와 Google Play다.

**일기를 쓰면 감자가 자라는, 귀여운 기록 습관**을 핵심 메시지로 사용한다. 기록을 꾸준히 남기고 싶은 한국 사용자에게 감자 성장의 즐거움과 감정·사진 기록 기능을 함께 전달한다.

## 반영 상태

| 항목 | 저장소에서 준비한 내용 | 실제 스토어 반영 |
| --- | --- | --- |
| App Store 문구 | 한국어 등록 파일·콘솔 이름·부제·설명·키워드 | 1.0.17 제출 준비 중 초안에 저장 · 새 빌드와 심사 필요 |
| Google Play 문구 | 한국어 제목·간단한 설명·전체 설명 | 검토 전송 완료 · 자동 검사 중 |
| 스크린샷 | 플랫폼별 6장 제작·번호순 업로드 · 그래픽 이미지 교체 제외 | iOS 초안 저장 · Play 검토 전송 |
| 신규 제품 기능 | [시장 조사와 후보 우선순위](market-research-2026-10.md)만 기록 | 미구현 |

사용자 요청에 따라 develop의 감정 선택 화면을 기존 사각 카드 디자인으로 복원하고, 일기 읽기 본문의 줄 간격·제목·사진 여백을 다듬었다. 사진 일기 미리보기도 개선된 읽기 화면으로 다시 촬영했다. 감정·임시저장·완료 저장 로직은 유지했다. Google Play는 검토 전송 후 자동 검사 중이며, App Store는 1.0.17 초안 저장 상태다. 공개 반영은 아직 확인하지 않았다. 앱 아이콘·카테고리·릴리즈 노트·배포 설정은 변경하지 않았다. [콘솔 적용 기록](application-2026-10-19.md)을 참고한다.

## 등록 문구와 파일

등록용 텍스트 파일을 원본으로 사용한다. 문구를 수정하면 이 표와 양쪽 상세 설명도 함께 갱신한다.

| 필드 | 확정 문구·길이 | 등록 파일 |
| --- | --- | --- |
| App Store 이름 | 감자일기 - 감자 키우는 감정 일기장 · 20자 | [name.txt](../../fastlane/metadata/ko/name.txt) |
| App Store 부제 | 사진으로 남기는 하루, 귀여운 기록 습관 · 22자 | [subtitle.txt](../../fastlane/metadata/ko/subtitle.txt) |
| App Store 키워드 | 다이어리,한줄일기,기분,캐릭터,위젯,추억,일상,메모,임시저장 · 33자 / UTF-8 83바이트 | [keywords.txt](../../fastlane/metadata/ko/keywords.txt) |
| App Store 상세 설명 | 성장·감정·사진·위젯·임시저장·검색 소개와 선택 권한 안내 | [description.txt](../../fastlane/metadata/ko/description.txt) |
| Google Play 제목 | 감자일기 - 감자 키우는 감정 일기장 · 20자 | [title.txt](../../fastlane/play_metadata/ko-KR/title.txt) |
| Google Play 간단한 설명 | 매일의 기분과 사진을 남기며 감자를 키우는 일기장, 홈 위젯으로 이어가는 기록 습관 · 46자 | [short_description.txt](../../fastlane/play_metadata/ko-KR/short_description.txt) |
| Google Play 전체 설명 | App Store 상세 설명과 동일 | [full_description.txt](../../fastlane/play_metadata/ko-KR/full_description.txt) |

검색 의도는 일기장·감정 일기·한줄일기·사진 기록으로 잡고, 차별점은 감자 성장과 홈 위젯으로 설명한다. 키워드별 검색량·경쟁도는 검증하지 않았으므로 검색 순위 향상을 보장하는 목록이 아니다. Google Play에는 별도의 키워드 목록을 붙이지 않는다.

이름·부제는 각각 30자, Play 간단한 설명은 80자, 양쪽 상세 설명은 4,000자 이내로 관리한다. Apple의 키워드 안내에는 문자와 바이트 표기가 혼재하므로 이번 목록은 두 기준 모두 100 이내로 준비했다. 줄 끝 개행은 필드 내용으로 복사하지 않는다.

### 현재 기능과 문구의 일치

- [홈](../../lib/view/home/home_page.dart)과 [레벨 기준](../../lib/util/level.dart): 완료된 일기가 쌓이면 감자의 성장 단계가 달라진다. 한 편 작성으로 즉시 레벨이 오른다고 홍보하지 않는다.
- [감정 선택](../../lib/view/write/write_selecting_emotion.dart): 현재 8가지 감자 표정 중 하나를 선택한다. 완료 본문은 1자 이상 500자 이내다.
- [사진 도구](../../lib/view/write/write_editor_toolbar.dart)와 [텍스트 도구](../../lib/view/write/write_text_toolbar.dart): 사진 첨부와 글꼴·색 편집을 제공한다. 동영상 첨부나 무제한 작성을 약속하지 않는다.
- [위젯 데이터](../../lib/service/streak_service.dart): 공유 데이터에는 성장·연속 기록·주간 감정이 있다. 실제 [iOS 위젯](../../ios/PotatoDiaryWidget/PotatoDiaryWidget.swift)은 주간 감정 달력을, [Android 위젯](../../android/app/src/main/kotlin/com/jihyuk/potatodiary/PotatoDiaryWidget.kt)은 성장과 연속 기록을 보여준다. 공통 상세 설명은 양쪽 모두에 맞도록 '홈 위젯에서 일기 기록을 확인해요'로 작성했다.
- [임시저장](../../lib/service/draft_store.dart)과 [일기 검색](../../lib/view/diary/diary_search.dart): 이어쓰기와 제목·본문 검색을 제공한다. 기기 저장과 서버 동기화 완료를 구분한다.

2026-10-18 공개 페이지에서 확인한 교체 대상은 다음과 같다. [App Store](https://apps.apple.com/kr/app/감자일기/id6739600096)는 미니게임을 소개하는 이미지가 남아 있었고, [Google Play](https://play.google.com/store/apps/details?id=com.jihyuk.potatodiary&hl=ko)는 아이폰 프레임을 사용한 이미지 두 장을 제공했다. 양쪽 설명의 질문형 일기 안내도 현재 기능에 맞춰 교체한다. 미니게임·오늘의 질문·AI 분석은 새 등록 문구에 포함하지 않는다.

### 공통 스타일과 예시 데이터

- 배경은 크림색 `#FFF8EE`, 포인트는 앱의 하늘색 `#94CFE8`, 헤드라인은 갈색 `#49372B`를 사용한다. 기존 감자 손그림을 재사용한다.
- 헤드라인은 기존 Pretendard SemiBold로 최대 두 줄, 캔버스 폭의 약 7% 글자 크기를 사용한다. 상단 약 25%를 카피 영역으로 두고 좌우 여백은 폭의 8% 이상 확보한다. 화면·위젯은 나머지 영역에서 크게 보여준다.
- 헤드라인 외의 추가 홍보 문구·평점·후기·순위 배지는 넣지 않는다. 축소된 스토어 화면에서도 읽히는지 확인한다.
- 전용 시뮬레이터의 예시 프로필 이름은 '몽실이', 예시 글은 '퇴근길 노을'과 '친구와 먹은 저녁'으로 통일했다. 노을 사진은 제작용으로 생성한 풍경 이미지이며 출처·프롬프트를 자산 문서에 기록했다.
- 완료 일기 42편·EXP 42·LV.3·현재 진행 8/23을 사용했다. 최근 7일의 완료 기록 앞에 하루 공백을 두어 Android 위젯의 7일 연속 표시와 맞췄다. 초안 세 편은 완료 편수에 포함하지 않는다. 날짜는 촬영 시점의 한국 날짜를 따른다.
- 최종 캔버스 크기 변경 시 화면을 늘려 왜곡하지 않고 카피와 촬영 화면의 배치를 다시 맞춘다.

### 플랫폼별 출력

| 대상 | 출력 규격 | 플랫폼 차이 |
| --- | --- | --- |
| App Store iPhone | 세로 1320×2868 PNG, 6장 | 실제 iPhone 화면과 얇은 프레임을 사용한다. |
| Google Play 휴대전화 | 세로 1080×1920 PNG, 알파 없음, 6장 | 실제 Android 화면을 사용하고 아이폰 프레임·Dynamic Island를 넣지 않는다. |

iPad·태블릿·다른 플랫폼 지원을 이번 제작안으로 확대하지 않는다. 실제 지원하는 기기와 현재 콘솔에서 요구하는 디스플레이 유형은 게시 전에 확인한다.

### 적용 제외 항목

사용자 요청에 따라 새 Google Play 그래픽 이미지(`featureGraphic.png`, 1024×500)는 적용에서 제외한다. 기존 스토어 그래픽 이미지를 유지하며 갤러리와 업로드용 ZIP에는 양쪽 스크린샷 12장만 포함한다. 제작한 그래픽 파일은 참고용으로만 보관한다.

## 스토어 적용 절차

### App Store

1. 다음 iOS 릴리즈 준비 시 한국어 이름·부제·키워드·설명을 위 등록 파일과 대조한다.
2. [기존 Fastlane 설정](../../fastlane/Fastfile)은 `fastlane/metadata`를 읽고 `skip_screenshots: true`로 동작한다. 새 문구는 릴리즈 제출 대상이지만 이 변경만으로 게시되거나 새 버전이 만들어지지 않는다.
3. 이미지 제작 후 App Store Connect의 한국어 iPhone 미디어에서 기존 세 장을 새 여섯 장으로 교체하고 순서를 확인한다. 현재 자동화는 이미지를 올리지 않는다.
4. 기존 저장소 릴리즈 절차에 따라 승인된 릴리즈에서 제출한다. 로컬에서 `submit` lane을 실행하지 않는다.
5. 심사·출시 후 공개 페이지의 이름·부제·설명·이미지를 다시 확인한다. 비공개 키워드는 콘솔의 저장된 값으로 확인한다.

### Google Play

1. Play Console에서 `com.jihyuk.potatodiary`의 한국어 기본 스토어 등록정보를 연다.
2. 제목·간단한 설명·전체 설명에 각각 등록 파일의 내용을 붙여 넣는다. 다른 언어는 수정하지 않는다.
3. 이미지 제작 후 기존 휴대전화 이미지 두 장을 새 여섯 장으로 교체한다. 기존 그래픽 이미지는 유지한다.
4. 콘솔 미리보기에서 줄바꿈·잘림·이미지 순서를 확인하고 게시 검토 절차를 거친다.
5. 공개 페이지에 반영됐는지 확인한다. 기존 Android lane은 `skip_upload_metadata`, `skip_upload_images`, `skip_upload_screenshots`가 모두 `true`여서 이 파일들을 자동으로 올리지 않는다. 이번 작업에서는 해당 설정을 바꾸지 않는다.

Android 파일은 iOS의 언어 디렉터리로 오인되지 않도록 `fastlane/play_metadata`에 분리했다. 이후 자동화를 추가한다면 이 디렉터리를 Android `metadata_path`로 지정하는 별도 변경에서 검토한다.

## 검증과 성과 확인

- 텍스트 필드의 길이·UTF-8 인코딩·끝 개행, 키워드 중복·불필요한 공백, 양쪽 상세 설명 일치를 확인한다.
- 문구를 현재 기능과 대조하고 문서의 로컬 참조 경로를 확인한다. `git diff --check`를 실행한다. 감정 선택 화면의 사각 카드 복원과 읽기 본문의 줄 간격·제목·사진 여백 개선 외에 모델·빌드 설정은 유지하며 촬영용 entrypoint와 내보내기 도구를 별도로 사용한다.
- 촬영용 Dart 도구의 포맷·정적 분석, 기존 Flutter 테스트와 플랫폼별 촬영 앱 실행을 확인한다. 제품 테스트는 추가하지 않는다.
- 각 OS의 성장·감정·사진·네이티브 위젯·검색·이어쓰기 화면, 스토어 축소 크기의 가독성과 기기 하단 잘림을 검토한다. 적용할 12개 스크린샷의 크기·PNG 인코딩·Google Play 알파 채널 부재를 확인한다. 최종 스토어 콘솔 미리보기는 업로드 시 다시 확인한다.
- 게시일과 변경 필드를 기록하고, 가능하면 적용 전후 각 28일의 한국 검색 유입·다운로드·전환율을 스토어별로 비교한다. 광고 유입·기타 캠페인·앱 버전 변경은 함께 기록한다.
- 스토어별 지표 정의를 섞지 않으며 표본이 작으면 개선을 단정하지 않는다. 후속 실험은 첫 장만 바꾸고 '일기를 쓰면 감자도 자라요'와 '감자와 함께 만드는 일기 습관'을 비교한다. 이번 작업은 실험이나 분석 도구를 구현하지 않는다.
